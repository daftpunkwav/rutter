## 方法

按 audit-pipeline 顺序执行 12 个阶段：correctness → edge-case → security →
api-contract → decouple → dependency → performance → resilience →
maintainability → naming → doc → test。每个阶段由对应 subagent 审查并直接修
复，主 agent 逐行审核 diff、独立复跑验证命令（check/clippy/test/fmt，必要时
含 header/encoding 门禁与 rustdoc），通过后按"一 commit 一事"拆分提交（显式
路径 staging，未用 `git add -A`）。

## 各阶段结果

### 阶段 1 · 正确性（correctness-auditor-shaw）

| 严重度 | 问题 | 修复 |
|---|---|---|
| P1 | `Session::session()` 与 `start_running()` 双重 `spawn_recovery`，每次引擎重启恢复任务跑两遍（孤儿 tab、双份事件、重复回放） | 删除重复调用，保留 start_running 内单一任务 |
| P1 | dashboard WS 先 replay 后 subscribe，两步之间发布的事件永久丢失 | 先 subscribe 再取快照，watermark 去重 |
| P2 | `host_allowed` 前缀匹配放行 `127.0.0.1.evil.com`（DNS rebinding 防护失效） | 剥端口后精确匹配回环名 |
| P2 | `active_page()` 整体覆盖 pages 向量，并发下丢 tab（浏览器 tab 泄漏） | 锁内决策 + racing 败者关闭多余页 |
| P2 | `recover()` 按 URL 判定 active，同 URL 双 tab 双 active 破坏不变量 | 按下标判定 |
| P3 | auto-wait 三相共享单一预算、超时 phase 误报、`stability_sample_interval` 死配置 | 逐相预算（仅前进时重置）+ 相位跟踪 + 采样间隔真实生效 |
| P3 | MCP 截断标记 `...` 与 TOOL_SPEC §2 的 `…` 不符 | 改为契约字符 |

### 阶段 2 · 边界/异常（edge-case-auditor-shaw）

| 严重度 | 问题 | 修复 |
|---|---|---|
| P1 | `wait_for` 传 `u64::MAX` ms 使 `Instant + Duration` 溢出 panic | `poll_until` 钳制 `MAX_POLL_BUDGET`(600s)，单点覆盖 |
| P1 | `approval_timeout_ms = u64::MAX` 使 tokio timeout panic | `parse_policy` 拒绝超 24h 值（显式 ConfigError） |
| P2 | 浏览器侧 target 消失后 `close_page` 永久失败，幽灵 tab 占死页帽 | CloseTarget 失败时 `Target.getTargets` 复核，已消失则解除注册 |
| P2 | 空白 `url_pattern` 静默降级为匹配所有 URL | 拒绝而非放宽 |
| P2 | storage 状态文件非原子写，崩溃后半写损坏丢登录态 | 临时文件 + rename 原子替换 |
| P3 | decision-ack 字符串拼接 JSON，request_id 可注入畸形 | serde_json 构造 |
| P3 | `file://` 等不透明源上 localStorage 抛异常使 evaluate 失败 | 脚本 try/catch，返回 `{unavailable: true}` |
| P3 | i18n fetch 失败（bind 竞态）使 dashboard 永不连接 | `.catch` 兜底直接 connect |

### 阶段 3 · 安全（security-auditor-shaw）

威胁模型按 BLUEPRINT §7.7（单用户本地机器）校准，未过度加固。

| 严重度 | 问题 | 修复 |
|---|---|---|
| P1 | dashboard token 用固定 key DefaultHasher(time+pid)，熵 ~2^25-2^35，本机进程可秒级爆破后架空审批 | `RandomState`（OS 熵种子）派生 |
| P1 | token 存 localStorage，违反 BLUEPRINT §7.7 "exchanged for a cookie" 契约 | HttpOnly SameSite=Strict 会话 cookie 交换；前端不再持久化；`cookie_safe` 保证非法 override token 退回 query；query 路径保留（e2e 兼容） |
| P2 | cookies/localStorage 明文文件 0644 | Unix 上 `OpenOptions::mode(0o600)` 创建时生效 |
| P2 | 引擎下载 URL 未校验 scheme（TLS 下的降级纵深） | 非 https 的 artifact URL 判 malformed |
| P3 | `--http` 非 loopback 绑定无提示 | 绑定时 stderr 警告（rmcp Host 校验 fail-closed 已核实源码） |

评估为非问题：`--engine-arg` 透传（CLI 用户=本机所有者）、policy 按"动作发生时页面 URL"匹配（TOOL_SPEC 语义，恶意网页自身导航不经 rutter 执行器）、zip 声明大小预分配（前提需先破 TLS manifest）。

### 阶段 7 · 性能（performance-auditor-shaw）

| 严重度 | 问题 | 修复 |
|---|---|---|
| P1 | 每次动作后无条件全量重写 storage 文件 | 与 `last_storage` 比较，无变化且上次成功则跳过；失败强制重试 |
| P2 | broadcast Lagged 后 dashboard 静默丢事件直到重连（违反 bus.rs 自述 + §7.5） | 从各 session ring 补发 `sent_up_to` 之后的事件，按 seq 排序去重 |
| P3 | 快照路径 envelope 两次深拷贝（大页面 MB 级） | 借用传递，仅字符串分支 parse |

审查为健康：ring 有界、auto-wait 轮询成本受契约约束、rmcp schema 构造期一次
性、CDP 调用包装开销可忽略。builder `subtree_size` 有界非 O(n²)，未动。

### 阶段 8 · 韧性（resilience-auditor-shaw）

| 严重度 | 问题 | 修复 |
|---|---|---|
| **P0** | recovery 任务缓存死引擎 `Arc`，引擎重启后所有 context 创建永远失败——恢复机制整体失效 | `Running` 不再存引擎，统一经 `supervisor.engine()` 现取（session/recovery 两处） |
| P1 | serve 模式无 Ctrl-C 处理、退出无 `manager.shutdown()` | stdio `select!` 合并断开+Ctrl-C；HTTP 补 Ctrl-C；所有退出路径统一 shutdown |
| P1 | `start_running` 失败遗弃 supervisor 心跳孤儿（后台反复拉起无主浏览器） | 失败路径 `supervisor.shutdown()` |
| P1 | `close_session` 从不 dispose browser context，HTTP 反复连接无限累积 context | `ContextHandle::close()`（幂等，"not found" 视为成功）；Session.close 走 context 级关闭 |
| P2 | `page.url()` 裸 oneshot await（handler 卡死则永久挂起）+ screencast 四处无界 CDP 调用 | 全部包 deadline |
| P2 | session 数无上限 | `max_sessions`（默认 8）容量上限 |
| P3 | close_session 后 OnceCell 缓存复活已关闭 session | `session()` fail-fast 校验 |
